# Baby Tracker「AI 育儿助手」总体规划

> 文档状态：方向评审草案  
> 文档版本：0.1  
> 更新日期：2026-07-22  
> 说明：本文描述最终方向与版本演进，不等同于 V1 开发范围。

## 1. 功能定位

AI 育儿助手是 Baby Tracker 现有应用中的智能辅助功能，不是独立产品。

它复用应用当前家庭、当前宝宝以及喂养、睡眠、尿布、生长、健康、疫苗和发育记录，帮助家庭成员理解记录、获取日常育儿建议和识别需要关注的风险。

现有记录与统计功能始终是数据源和事实来源。AI 的职责是解释、归纳和引导，不取代记录功能，不自动篡改记录，也不替代医生诊断。

## 2. 最终体验目标

最终形态应做到：

1. 用户在现有应用内直接提问，不需要理解供应商、Key 或模型参数。
2. AI 自动理解当前家庭和当前宝宝，但让用户知道本次使用了哪些数据。
3. AI 可以回答通用问题，也可以解读宝宝近期记录和长期趋势。
4. AI 能识别危险症状并优先展示就医提示。
5. AI 可以从统计、睡眠、喂养等现有页面被上下文唤起。
6. 家庭和宝宝切换后，上下文、会话与历史严格隔离。
7. 模型供应商、Key、模型映射和故障回退由服务端统一管理。
8. 未来可接入权威育儿知识库，但回答必须区分记录事实、知识来源和模型推测。

目标体验示例：

> 最近 7 天宝宝平均睡眠比前一周减少约 1 小时，夜间短时醒来记录增加。结合当前月龄，可以先检查白天小睡和睡前流程。现有记录不足以判断医学原因；若同时出现精神差、呼吸异常或持续发热，应尽快就医。

## 3. 能力地图

### 3.1 问答能力

- 通用育儿知识问答。
- 连续多轮对话。
- 按月龄调整回答。
- 根据问题自动选择必要记录。
- 模型选择和供应商回退。
- 回答复制、反馈与重新生成。

### 3.2 数据理解

- 喂养次数、总量和时间分布解读。
- 睡眠总时长、昼夜分布和变化趋势解读。
- 尿布、排便和尿湿频率解读。
- 身高、体重、头围趋势解读。
- 体温、症状和健康事件整理。
- 疫苗计划和发育评估说明。
- 跨类别关联，例如睡眠变化与喂养记录的时间关系。

### 3.3 安全能力

- 输入前本地风险预判。
- 月龄、温度、症状组合规则。
- 模型安全 Prompt。
- 回答后本地安全校验。
- 紧急、高风险、需关注和一般四级提示。
- 独立于模型回答的风险卡片。

### 3.4 应用内联动

- 首页统一入口。
- 助手页集中提供睡眠、喂养、健康和近期概览。
- 助手按当前宝宝读取记录，不在各业务页面增加 AI 入口。
- 回答只提供建议，不自动修改业务数据。

### 3.5 历史与家庭协作

- 本地会话历史。
- 按宝宝查看会话。
- 会话标题、删除和搜索。
- 是否向家庭成员共享会话需单独授权。
- 重要回答可由用户主动保存为备注或分享。

### 3.6 专业内容

- 权威育儿知识库检索。
- 回答显示资料来源和更新时间。
- 对时效性健康内容进行版本管理。
- 知识库内容与模型回答分层展示。

### 3.7 多模态与主动洞察

- 语音提问与朗读。
- 图片识别仅用于低风险辅助描述，不用于诊断。
- 周报、月报和成长摘要。
- 发现明显趋势后生成可关闭的洞察卡片。
- 任何主动提醒必须可解释、可关闭且避免制造焦虑。

## 4. 与现有应用的边界

| 现有模块 | AI 的作用 | 不允许的行为 |
|---|---|---|
| 家庭 | 使用当前家庭作为权限范围 | 自建独立家庭状态 |
| 宝宝 | 使用当前宝宝作为上下文 | 跨宝宝混用记录 |
| 记录 | 读取必要摘要 | 未经确认自动新增或修改记录 |
| 统计 | 解释已有结果 | 生成与统计逻辑矛盾的伪数据 |
| 健康 | 整理信息和风险提示 | 医疗诊断、处方或替代就医 |
| 消息中心 | 无直接复用 | 把 AI 会话写入站内信 `messages` 表 |
| 同步 | 后续可同步独立 AI 表 | 直接把 AI 表塞入现有同步列表 |

## 5. 长期信息架构

```text
Baby Tracker
  ├── 首页
  │    ├── 育儿助手入口
  │    └── AI 洞察卡（后续）
  ├── 记录功能
  ├── 统计
  ├── AI 育儿助手
  │    ├── 当前宝宝与数据范围
  │    ├── 睡眠 / 喂养 / 健康 / 近期概览
  │    ├── 对话
  │    ├── 推荐问题
  │    ├── 风险提示
  │    └── 历史会话（后续）
  └── 设置
       ├── AI 数据使用说明
       ├── 使用近期记录开关
       └── AI 功能开关（后续）
```

AI 不增加新的底部主导航项，避免挤占记录和统计等核心功能。

## 6. 数据上下文长期策略

### 6.1 原则

- 只选择当前问题必要的数据。
- 只使用当前家庭下当前宝宝的数据。
- 使用摘要而不是发送完整数据库。
- 无记录必须表示“无记录”，不能当作数值 0。
- 用户能看到本次使用的数据类别和时间范围。
- 用户可以关闭近期记录使用。

### 6.2 推荐时间范围

| 类别 | 默认范围 | 长期能力 |
|---|---|---|
| 宝宝档案 | 当前宝宝 | 月龄、性别、出生信息 |
| 喂养 | 最近 3 天 | 与前一周期对比 |
| 睡眠 | 最近 7 天 | 周趋势与昼夜分布 |
| 尿布 | 最近 3 天 | 频率与异常变化 |
| 生长 | 最近 90 天 | 长期曲线趋势 |
| 健康 | 最近 30 天 | 症状、体温与用药事件整理 |
| 疫苗 | 问题相关 | 已完成和近期计划 |
| 发育 | 最近评估 | 阶段性结果摘要 |

## 7. 安全边界

### 7.1 必须坚持

- AI 是育儿信息助手，不是医生。
- 不输出确定性诊断。
- 不建议擅自停药、换药或使用处方药。
- 不基于不完整信息计算儿童用药剂量。
- 危险症状必须优先建议联系专业医疗人员。
- 紧急提示由应用本地规则独立展示，不能完全依赖模型。

### 7.2 风险等级

| 等级 | 示例 | 应用行为 |
|---|---|---|
| 紧急 | 呼吸困难、嘴唇发紫、失去意识、持续抽搐 | 突出提示立即联系急救或就近就医 |
| 高风险 | 3 月龄以下发热、严重脱水、误食药物 | 建议尽快就医，限制居家建议 |
| 需关注 | 症状持续、喂养或尿量明显减少 | 给出观察指标和咨询时机 |
| 一般 | 作息、辅食、日常护理 | 正常回答并显示免责声明 |

## 8. 隐私与安全长期要求

1. 不向模型发送用户 ID、家庭 ID、手机号、Supabase Token 或数据库 ID。
2. API Key 不进入日志、Room、普通 SharedPreferences、崩溃报告或 UI。
3. 日志不记录问题和回答正文。
4. 家庭或宝宝切换立即取消请求并清理不匹配的会话上下文。
5. 对话同步必须默认关闭，启用前明确说明共享范围。
6. 公开发行前应把模型请求迁移到可信后端代理。

当前把可解密供应商 Key 下发到 Android 的方案只适合个人/家庭自用，无法从根本上阻止设备所有者提取 Key。

## 9. 版本路线

### V1：应用内可用问答

目标：完成安全、稳定、能结合少量宝宝数据的基础问答。

- 首页入口和聊天页面。
- 均衡/深度模型选择。
- 内存会话和多轮对话。
- 当前宝宝档案与有限近期记录。
- 基础风险规则和免责声明。
- 推荐问题、复制、重试和停止。
- 不修改 Room，不保存历史。

详细范围见 [AI育儿助手V1功能PRD](AI育儿助手V1功能PRD.md)。

### V2：记录解读与本地历史

目标：让助手真正成为现有记录功能的解释层。

- 更完整的记录摘要与周期对比。
- 在助手页集中选择睡眠、喂养、健康和近期概览上下文。
- 独立 AI 会话表和本地历史。
- 会话搜索、删除和按宝宝筛选。
- 更完整的风险规则测试集。

助手页集中快捷分析与统一对话上下文见 [AI育儿助手V2第一阶段PRD](AI育儿助手V2第一阶段PRD.md)。

周期对比与跨类别趋势解释见 [AI育儿助手V2第二阶段PRD](AI育儿助手V2第二阶段PRD.md)。

本地会话历史、搜索、删除和家庭/宝宝隔离见
[AI育儿助手V2第三阶段PRD](AI育儿助手V2第三阶段PRD.md)。

V2 第三阶段采用 Room 7→8 迁移，AI 会话保持纯本地且不加入同步。

### V3：知识与家庭协作

目标：提升回答可信度并支持可控共享。

- 权威育儿知识库与来源展示。
- 家庭会话共享策略。
- 云端独立 AI 表、RLS 和同步设计。
- 回答反馈和质量评估。
- 周/月总结。

V3 开始前必须评审数据合规、RLS、同步冲突与内容更新机制。

### V4：多模态与主动助手

目标：在安全可控的前提下提供更自然的交互。

- 语音输入与朗读。
- 谨慎的图片辅助分析。
- 主动趋势洞察。
- 多供应商智能路由和成本策略。
- 可信后端模型代理。

## 10. 技术架构演进

### 当前至 V1

```text
Android
  → Supabase ai-bootstrap 获取加密配置
  → Android 直接调用模型供应商
```

适合个人/家庭自用，部署简单，但客户端凭据存在可提取风险。

### 公开发行阶段

```text
Android
  → 可信 AI 网关
      → 身份与家庭权限
      → 限流与预算
      → 安全规则
      → 知识库
      → 多模型供应商
```

迁移触发条件包括公开发行、用户规模扩大、需要严格限流、供应商协议复杂化或无法接受客户端 Key 风险。

## 11. 长期质量指标

| 指标 | 目标 |
|---|---|
| 家庭或宝宝串数据 | 0 |
| 高风险测试集漏提示 | 0 |
| 使用上下文但不展示数据依据 | 0 |
| 重复发送导致重复计费 | 0 |
| 问答技术成功率 | ≥ 95% |
| 配置获取成功率 | ≥ 99% |

## 12. 版本立项规则

每个版本开始前必须单独形成 PRD，并明确：

1. 本版用户问题与目标。
2. 范围与明确不做事项。
3. 数据读取与保存范围。
4. 安全规则变化。
5. 数据库、同步或服务端影响。
6. UI 流程和验收标准。
7. 测试集和回滚方案。

总体规划中的能力不能直接视为已批准开发。
