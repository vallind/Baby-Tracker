# Baby Tracker「AI 育儿助手」V2 第四阶段 PRD

> 文档状态：已实现
> 文档版本：0.1
> 更新日期：2026-07-24
> 阶段范围：回答修订、依据分层与本地保存状态

## 1. 阶段目标

让用户可以安全地修订最后一轮问答，并清楚区分宝宝记录、AI 推断和行动建议；本地历史保存失败时必须明确提示，但不能遮挡已经生成的回答。

## 2. 用户流程

```text
完成一轮回答
  ├─ 重新生成 → 移除旧回答 → 使用同一问题重新请求
  ├─ 编辑问题 → 回退该轮问答 → 原问题回到输入框 → 修改后发送
  └─ 查看回答依据 → 展开记录事实、AI 解读和行动建议
```

## 3. 回答修订

- “重新生成”只对最后一个完整问答轮次开放。
- 重新生成前先移除旧回答，避免页面和本地历史出现同一问题的重复回答。
- “编辑问题”同时移除最后一个问题及其回答，把原问题放回输入框。
- 用户修改后需要主动发送，不自动调用模型。
- 发送、重试、重新生成和停止都复用同一请求状态，生成中禁止重复触发。
- 重新生成仍经过宝宝上下文构建、健康问题缓冲和完整回答安全校验。

## 4. 回答依据

完成态回答提供可展开的依据区：

- **记录事实**：展示本次实际使用的本地记录分类和时间范围；没有引用时明确说明未使用近期记录。
- **AI 解读**：说明正文中的关系解释属于模型推断，不代表已确认的因果关系或诊断。
- **行动建议**：保留育儿参考和不能替代医生诊断的提示。

依据区只解释回答来源和可信边界，不把模型正文自动改写成结构化医学结论。

## 5. 本地保存状态

- 正在写入 Room 时显示“正在保存本地对话”。
- 写入成功后显示“对话已保存到本机”。
- 写入失败时显示明确提示，同时保留当前页面中的问题和回答。
- 保存失败不自动重复模型请求，不影响复制和重新生成。
- 编辑问题后的截断会话会覆盖原会话消息，不新增重复会话。

## 6. 隔离与中断

- 所有保存状态只更新发起保存时的家庭和宝宝。
- 切换家庭或宝宝后，旧请求和旧保存结果不能注入当前页面。
- 手动停止保留已显示的部分回答，并通过同一会话覆盖保存。
- 思考内容继续与最终回答分离，且不进入下一轮模型上下文。

## 7. 验收标准

1. 最后一条完整回答可重新生成，旧回答不残留。
2. 最后一个问题可编辑，旧问题和旧回答同时从当前轮次移除。
3. 连续点击发送、重试或重新生成不会创建并行请求。
4. 重新生成后的回答仍通过安全校验。
5. 回答依据默认收起，展开后能看到记录事实、AI 推断边界和行动建议提示。
6. 历史保存失败有可见提示，当前回答不丢失。
7. 编辑或重新生成后，本地历史按消息顺序覆盖，不产生重复消息。
8. 不修改 Room 表结构、后端、业务页面或导航。

## 8. 不实现

- 不自动判断正文中每一句属于事实、推断还是建议。
- 不新增云端历史、家庭共享、收藏、导出或知识库。
- 不在睡眠、喂养、健康和统计页增加入口。
- 不启动模拟器验证，除非用户另行要求。
