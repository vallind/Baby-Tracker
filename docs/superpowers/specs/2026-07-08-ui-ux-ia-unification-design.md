# UI/UX/IA 统一改造设计

## 背景

项目已经具备令牌、主题和 Design System 组件，但页面级构图、功能层级与交互反馈仍不统一。本次改造保留现有功能能力，以“温柔陪伴”为视觉方向，同时优化信息架构和高频记录效率。

## 目标

- 建立跨页面一致的视觉层级、间距、圆角和护理类型颜色。
- 让用户在首页快速判断当前护理状态、下一项提醒和今日动态。
- 高频护理记录从首页一步打开，其他记录通过全局入口两步打开。
- 保留功能宫格，默认展示 8 项，其余功能进入“更多”。
- 家庭成员能够清楚识别记录人和同步状态。

## 非目标

- 首版不实现基于历史数据的喂养或睡眠预测。
- 不重写现有数据层、同步流程或业务规则。
- 不为单次页面形态新增 Design System 组件。
- 不一次性重做全部业务页面。

## 信息架构

### 一级导航

底部导航固定为四项：

1. 首页
2. 时间线
3. 统计
4. 我的

底部中央 `＋` 是全局记录入口，不占用独立导航页面。点击后打开记录类型选择层，再进入对应表单。

“我的”统一承载宝宝管理、家庭协作、消息和设置。成长、疫苗、健康等低频功能保留在首页功能宫格和“更多”页，不增加底部导航项。

### 首页职责

首页只回答四个问题：

1. 当前是否有正在进行的护理？
2. 接下来有什么真实提醒？
3. 如何快速新增护理记录？
4. 今天刚发生了什么？

首页不承担完整历史查询、复杂趋势分析或设置任务。

## 首页布局

页面从上到下依次为：

1. 宝宝信息、当前日期和宝宝切换入口。
2. 主状态卡：有进行中护理时显示计时和操作；否则显示最近的下一项提醒；两者都没有时显示紧凑空状态。
3. 高频快捷记录：喂养、睡眠、尿布和成长，点击后直接打开具体表单。
4. 功能宫格：固定为 2×4，共 8 项，依次为喂养、睡眠、尿布、成长、发育评估、疫苗、健康和提醒；区块标题旁提供“更多”入口承载其余功能。统计不在宫格重复出现，统一从底部导航进入。
5. 今日最近记录：按时间倒序展示有限条目，并提供前往完整时间线的入口。

同一时刻只允许一个强视觉焦点。进行中护理优先级高于提醒；无进行中护理时，提醒卡成为焦点。

## 视觉系统

### 风格

采用“温柔陪伴”：暖白背景、低饱和功能色、克制阴影和清晰文字层级。暖色只用于品牌和重点状态，不使用大面积粉色覆盖页面。

### 页面规则

- 页面水平边距统一为 `16dp`。
- 主要区块间距使用 `20–24dp`。
- 卡片内部间距默认 `16dp`。
- 圆角只保留小控件、普通卡片、重点卡片三级，并从 `AppShapes` 派生。
- 容器优先依靠背景层级和描边区分，阴影只用于浮层或当前主焦点。
- 空状态不保留大面积空卡片，使用简短说明和明确操作。

### 护理类型颜色

喂养、睡眠、尿布、成长、健康等类型各自使用固定语义色。相同类型在首页、表单、时间线和统计中保持一致。颜色必须以 `containerColor` 和 `contentColor` 成对定义，并满足文字可读性要求。

## 交互与状态

- 中央 `＋`：打开全部记录类型选择层。
- 首页快捷入口：直接打开对应表单，减少一次选择操作。
- 计时护理：在首页主状态卡提供暂停、切换和完成；具体按钮按对应业务能力显示。
- 保存成功：关闭表单、刷新首页和时间线，并显示 Snackbar。
- 删除记录：统一使用 `snackbar.showUndo(onUndo = { ... })`。
- 家庭记录：时间线条目在需要时显示记录人。
- 同步异常：使用非阻塞提示，不遮挡新增和完成记录操作。
- 加载：使用既有 Skeleton 组件保持结构稳定。
- 错误：保留当前有效数据并提供重试入口。
- 空状态：提供与当前区块直接相关的首个操作。

## 无障碍与动效

- 主要点击区域不小于 `48dp`。
- 正文、辅助文本和功能色满足亮暗主题下的对比要求。
- 图标不能作为状态的唯一表达，关键状态同时提供文字。
- 动画时长和缓动只读取 `AppMotion`。
- 暗色主题只由 `theme.name == "night"` 决定。

## 分阶段路线图

### P0：规范与基线

- 建立页面级布局、护理类型颜色和状态优先级规范。
- 保存现有关键页面截图，建立亮暗主题对比基线。
- 确认首页 8 个功能宫格入口为喂养、睡眠、尿布、成长、发育评估、疫苗、健康和提醒。

### P1：首页闭环

- 改造首页主状态、快捷记录、2×4 功能宫格和今日记录。
- 实现中央记录入口和“更多”页。
- 调整底部导航为首页、时间线、统计、我的。

### P2：高频记录

- 统一喂养、睡眠、尿布和健康的表单、列表、计时与反馈。
- 保持业务逻辑不变，只收敛交互和视觉表达。

### P3：数据密集页面

- 统一成长、疫苗、统计和完整时间线。
- 收敛筛选、图表、分段控件和空状态。

### P4：个人与协作

- 整理“我的”、宝宝管理、家庭、消息和设置的信息层级。
- 统一成员身份、同步状态和异常反馈。

### P5：质量收尾

- 完成暗色主题、字体缩放、触控区域和对比度检查。
- 补充截图回归、关键路径 UI 测试、性能检查和动效收敛。

### P6：预测能力评估

- 在积累足够真实记录后，再单独设计喂养和睡眠预测。
- 预测必须显示依据和不确定性，不能伪装成精确提醒。

## 验收标准

- 首页高频记录入口一步打开对应表单。
- 全局入口两步内打开任意记录表单。
- 首页首屏能够识别当前护理或下一项提醒。
- 功能宫格稳定显示 8 项，其余功能可从“更多”到达。
- 同一护理类型在首页、时间线和统计中使用一致颜色。
- 亮色、夜间主题和大字体下无文字截断、低对比或不可点击控件。
- 关键页面通过截图对比，核心记录路径通过 UI 测试。
- `assembleDebug` 与 `lint` 通过。

## 参考原则

方案借鉴成熟宝宝记录产品中已验证的模式：Nara Baby 的状态活动流、Huckleberry 的高频记录入口，以及 Baby Daybook 对进行中计时和今日时间线的优先展示。只采用信息组织原则，不复制其品牌视觉或专有能力。
