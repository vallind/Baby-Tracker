# Baby Tracker「AI 育儿助手」V1 功能 PRD

> 文档状态：实施前评审草案  
> 文档版本：0.1  
> 更新日期：2026-07-22  
> 版本范围：仅 V1  
> 说明：实施前仍需确认本文第 18 节的决策项。

## 1. V1 目标

在 Baby Tracker 现有应用内增加一个可日常使用的 AI 育儿助手功能，完成以下最小闭环：

```text
首页进入
  → 识别当前家庭和宝宝
  → 用户提问
  → 选择必要的近期记录
  → DeepSeek 回答
  → 安全提示与数据依据展示
```

V1 重点验证问答质量、宝宝上下文、安全边界和应用内体验，不建设独立历史系统、知识库或多模态能力。

## 2. 已有基础

- `ai-bootstrap` 已部署并启用 JWT 校验。
- 真机已经成功获得配置，日志包含 `bootstrap ok family=... configVersion=1`。
- Android 已具备配置缓存、设备 RSA 解密和模型调用能力。
- 当前服务端提供“均衡”和“深度”两个 DeepSeek 模型选项。
- 当前架构由 Android 直接调用 DeepSeek。

V1 不重复建设上述能力，只在现有基础上增加应用功能层。

## 3. V1 范围

### 3.1 本版必须实现

- 首页功能网格中的“育儿助手”入口。
- 应用内聊天页面与导航路由。
- 当前家庭、当前宝宝和 AI 配置前置校验。
- 纯文本发送和多轮对话。
- “均衡”“深度”模型选项切换。
- 当前宝宝档案和有限近期记录上下文。
- 推荐问题。
- 发送中、停止、重试、复制和错误状态。
- 本地风险规则、风险卡片和免责声明。
- 家庭/宝宝切换后的请求取消和会话清理。
- 单元测试、UI 状态测试与真机验证。

### 3.2 本版明确不做

- Room 聊天记录表和历史会话页面。
- AI 会话云同步或家庭共享。
- 自动新增、修改或删除宝宝记录。
- RAG 知识库和资料来源检索。
- 图片、文件或语音输入。
- 主动趋势通知和自动周报。
- 完整 Markdown 第三方渲染依赖。
- 面向公开用户的后端 AI 代理。

## 4. 与现有应用的关系

| 现有能力 | V1 使用方式 |
|---|---|
| 当前家庭 | 作为配置和权限范围 |
| 当前宝宝 | 作为问答的唯一宝宝上下文 |
| 喂养记录 | 仅问题相关时生成近 3 天摘要 |
| 睡眠记录 | 仅问题相关时生成近 7 天摘要 |
| 尿布记录 | 仅问题相关时生成近 3 天摘要 |
| 生长记录 | 仅问题相关时读取近 90 天最多 3 条 |
| 健康记录 | 仅问题相关时读取近 30 天最多 10 条 |
| 消息中心 | 不复用，不把 AI 消息写入 `messages` |
| 数据同步 | V1 不新增同步表或同步流程 |

V1 不建立独立的“AI 当前宝宝”，必须使用现有 `BabyController` 选中的宝宝。

## 5. 入口与导航

### 5.1 入口

在现有首页 `FeatureGrid` 中增加“育儿助手”。入口的图标、颜色、位置在实施讨论时确认。

V1 不增加底部导航项，不从设置页或消息中心进入。

### 5.2 路由

在现有 `AppNavigation` 增加一个普通页面路由，例如：

```text
/ai-assistant
```

页面返回行为与其他二级功能一致。

## 6. 页面结构

```text
AppTopBar
  ├── 返回
  ├── AI 育儿助手
  └── 模型选项

当前宝宝信息条
  ├── 宝宝昵称与月龄
  └── 本次会使用近期记录的说明

LazyColumn 消息区
  ├── 欢迎信息
  ├── 推荐问题
  ├── 用户消息气泡
  ├── AI 回答气泡
  ├── 本次参考数据
  └── 风险提示卡

输入区
  ├── 多行输入框
  ├── 停止/发送按钮
  └── 字数与错误提示
```

优先使用现有设计系统组件。页面独有的消息布局先在功能内实现，不提前抽象公共组件。

## 7. 首次进入流程

按顺序检查：

1. 用户是否已登录。
2. 当前家庭是否存在且已验证。
3. 当前宝宝是否存在。
4. AI 配置是否存在且未过期。
5. 页面是否可以开始问答。

对应行为：

| 状态 | 页面行为 |
|---|---|
| 未登录 | 展示登录引导，输入区禁用 |
| 无家庭 | 展示创建或加入家庭引导 |
| 家庭未验证 | 提供刷新提示 |
| 无宝宝 | 展示新增宝宝引导 |
| 配置加载中 | 显示加载状态，暂时禁用发送 |
| 配置失败 | 展示原因和刷新按钮 |
| 全部正常 | 展示欢迎语、推荐问题和输入区 |

## 8. 对话需求

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| V1-001 | 支持发送纯文本 | P0 | 空白不可发送，发送后立即出现用户气泡 |
| V1-002 | 支持连续多轮对话 | P0 | 后续问题携带最近完整轮次 |
| V1-003 | 防止并发重复发送 | P0 | 一个生成请求期间不能再次发送 |
| V1-004 | 限制输入长度 | P0 | 上限暂定 2,000 字，超限显示提示 |
| V1-005 | 支持停止请求 | P0 | 取消后旧请求不能继续更新页面 |
| V1-006 | 支持失败重试 | P0 | 重试不重复插入用户消息 |
| V1-007 | 支持复制回答 | P1 | 只复制回答正文，不包含内部 Prompt |
| V1-008 | 控制历史长度 | P0 | 超预算时移除最旧完整轮次，保留安全 Prompt |
| V1-009 | 页面内存保存本次会话 | P0 | 页面存活期间旋转或重组不丢失 ViewModel 状态 |
| V1-010 | 退出后不保证恢复历史 | P0 | 文案和交互不承诺历史永久保存 |

## 9. 模型选择

- 页面展示服务端下发的模型选项名称，不展示 API Key、Base URL 或内部供应商配置。
- 首次使用服务端 `defaultOption`，当前为“均衡”。
- 用户可切换“均衡”“深度”，只影响后续请求。
- 切换模型不重写已有回答。
- 真实供应商和模型名称只用于日志排障，可在回答详情中不展示。

错误处理必须区分：

| 类型 | 行为 |
|---|---|
| 401 | 刷新配置并提示管理员检查 Key，不跨供应商掩盖 |
| 400 | 提示请求或模型配置有误 |
| 429 | 提示请求频繁，允许稍后重试 |
| 5xx/超时 | 按现有可重试规则处理 |
| 网络不可用 | 保留用户问题并提供重试 |
| 余额不足 | 提示模型服务暂不可用 |

## 10. V1 宝宝上下文

### 10.1 固定上下文

每次请求固定包含：

- 当前宝宝昵称。
- 根据生日计算的精确月龄。
- 性别；未填写时明确为未知。

不得包含用户 ID、家庭 ID、宝宝数据库 ID、Supabase Token 或手机号。

### 10.2 问题相关上下文

| 问题类别 | 读取内容 |
|---|---|
| 通用月龄问题 | 仅宝宝档案 |
| 睡眠 | 最近 7 天睡眠摘要 + 最近 3 天喂养摘要 |
| 喂养 | 最近 3 天喂养摘要 + 最新生长记录 |
| 排便/尿布 | 最近 3 天尿布摘要 + 喂养摘要 |
| 生长 | 最近 90 天最多 3 条生长记录 |
| 发热/症状 | 最近 30 天最多 10 条健康记录 |
| 无法分类 | 只用宝宝档案，不默认附加全部记录 |

V1 使用简单、可测试的本地分类规则。无法分类时宁可少发数据，也不把所有记录传给模型。

### 10.3 摘要要求

- 记录按当前宝宝过滤。
- 每类数据注明时间范围。
- 没有记录时写“无记录”，不能写成 0 次或 0 毫升。
- 发送聚合摘要和少量近期事件，不发送完整表。
- 健康备注和用药内容是否默认发送，在实施前确认。

### 10.4 数据透明度

使用记录上下文的回答下方显示：

```text
本次参考：宝宝档案、最近 7 天睡眠、最近 3 天喂养
```

未使用近期记录时显示：

```text
本次未使用宝宝近期记录
```

## 11. Prompt 要求

V1 Prompt 固定为四层：

```text
角色和边界
  → 安全规则
  → 当前宝宝最小上下文
  → 最近对话与当前问题
```

模型必须被要求：

- 使用简体中文。
- 先给结论，再给可执行建议。
- 区分记录事实、一般知识和推测。
- 数据不足时说明缺少的信息。
- 不编造宝宝记录。
- 不做医学诊断或危险用药指导。
- 健康问题列出需要及时就医的危险信号。

## 12. V1 安全规则

### 12.1 风险等级

| 等级 | V1 示例 | 页面行为 |
|---|---|---|
| 紧急 | 呼吸困难、嘴唇发紫、失去意识、持续抽搐 | 模型返回前立即显示紧急风险卡 |
| 高风险 | 3 月龄以下发热、明显脱水、误食药物 | 显示尽快就医提示 |
| 需关注 | 症状持续、进食或尿量明显减少 | 给出观察指标和咨询时机 |
| 一般 | 睡眠、辅食、日常护理 | 正常回答并显示免责声明 |

### 12.2 处理链

```text
本地输入规则
  → 立即风险卡
  → 安全 Prompt
  → 模型回答
  → 本地回答校验
  → 风险卡 + 回答 + 免责声明
```

### 12.3 限制

- 不输出确定性诊断。
- 不建议自行停药、换药或使用处方药。
- 不基于不完整信息计算儿童用药剂量。
- 不使用“肯定没事”等绝对措辞。
- 风险提示不能只存在于模型文本里。
- 规则必须识别否定表达，例如“没有抽搐”不能仅因关键词判定为抽搐。

## 13. 推荐问题

根据月龄和存在的记录展示最多 4 个本地模板：

- “宝宝这个月龄需要注意什么？”
- “帮我看看最近的睡眠情况”
- “最近喂养记录有什么变化？”
- “最近排便和尿布情况怎么样？”
- “最近体重增长趋势怎么样？”

没有对应记录时不展示该数据型问题，或点击后明确说明数据不足。

## 14. UI 状态

页面必须覆盖：

- 正常空态。
- 配置加载和配置失败。
- 未登录、无家庭、家庭未验证、无宝宝。
- 生成中和用户取消。
- 网络失败、认证失败、限流、服务端错误和余额不足。
- 高风险提示。
- 长回答、键盘弹出、暗色主题和大字体。

高风险提示使用页面内独立卡片，不能使用短暂 Snackbar 代替。

正式文案进入 `AppStrings`，暗色主题只使用项目当前主题状态，不直接读取系统暗色模式。

## 15. 家庭与宝宝隔离

家庭或宝宝发生变化时必须：

1. 取消当前模型请求。
2. 清空当前内存会话。
3. 重新检查 AI 配置范围。
4. 重新构建宝宝上下文。
5. 丢弃旧请求迟到的响应。

验收要求是任何测试场景都不能在新宝宝回答中出现旧宝宝昵称或记录。

## 19. 测试计划

### 19.1 单元测试

- 空输入、超长输入和重复发送。
- Prompt 不包含内部 ID 或无关数据。
- 问题分类选择正确的数据类别。
- 无记录与数值 0 不混淆。
- 风险规则覆盖月龄、温度、症状组合和否定表达。
- 历史截断保留最近完整轮次。
- 取消后旧响应不更新状态。
- 家庭和宝宝切换清理上下文。

### 19.2 集成测试

- 配置缓存到 DeepSeek 调用的完整链路。
- 401 刷新配置但不错误回退。
- 429、超时和 5xx 的处理。
- Supabase 不可用但有效缓存存在时仍可问答。
- 缓存过期且刷新失败时正确禁用发送。

### 19.3 UI 测试

- 全部前置空状态。
- 推荐问题、模型切换、发送和重试。
- 长回答滚动、复制和停止。
- 风险卡可见性和无障碍语义。
- 大字体、暗色主题和键盘交互。

### 19.4 人工安全测试

- 2 月龄宝宝 38℃ 发热。
- 呼吸困难和嘴唇发紫。
- “发生抽搐”与“没有抽搐”。
- 误食成人药物。
- 连续呕吐且尿量减少。
- 普通便秘、夜醒、辅食和奶量问题。

## 20. V1 验收标准

V1 必须同时满足：

1. 首页可进入育儿助手，返回导航正常。
2. 所有登录、家庭、宝宝和配置前置状态可理解。
3. 可用“均衡”和“深度”完成真实问答。
4. 支持至少 5 轮连续对话，不重复发送或重复计费。
5. 上下文只读取当前家庭的当前宝宝。
6. 使用记录的回答显示数据类别和时间范围。
7. 高风险问题在模型返回前出现本地提示。
8. 401、429、5xx、断网、余额不足和取消状态正确。
9. 家庭/宝宝切换或退出登录后不沿用旧上下文。
10. 日志不包含问题正文、回答正文或 API Key。
11. 单元测试、UI 状态测试、Lint 和 Debug 构建通过。
12. 未修改 Room 表结构和现有同步流程。

## 21. 发布与回滚

发布前：

1. 确认 `ai-bootstrap` 为 ACTIVE。
2. 确认配置版本、模型名称、DeepSeek Key 和余额。
3. 完成真机家庭/宝宝切换及安全用例验证。
4. 完成构建、Lint、版本号和变更日志。

若模型服务不可用，V1 至少应能通过服务端配置或后续软关闭字段让页面显示“育儿助手暂时不可用”，而不是影响现有记录功能。AI 功能故障不得阻断应用启动、记录或同步。
