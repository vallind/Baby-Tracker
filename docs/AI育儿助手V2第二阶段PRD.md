# Baby Tracker「AI 育儿助手」V2 第二阶段 PRD

> 文档状态：已实现
> 文档版本：0.1
> 更新日期：2026-07-24
> 阶段范围：周期对比与跨类别趋势解释

## 1. 阶段目标

在 AI 助手现有快捷分析中增加 7、14、30 天周期选择，把所选周期与紧邻的前一等长周期进行对比，让模型基于明确的两期数据解释变化。

本阶段继续只修改 AI 助手页，不在睡眠、喂养、健康和统计页面增加入口。

## 2. 用户流程

```text
进入 AI 助手
  → 选择 7 / 14 / 30 天
  → 选择睡眠、喂养、健康或近期概览
  → 自动填入可编辑的周期对比问题
  → 用户确认发送
  → AI 基于本期与前期记录回答
```

## 3. 实现范围

- 快捷分析区增加 7、14、30 天周期选择，默认 7 天。
- 睡眠、喂养、健康和近期概览统一使用所选周期。
- 本期范围为最近 N 天，前期范围为紧邻的前 N 天，边界记录只属于一个周期。
- 周期变化后重新读取当前宝宝记录并刷新可分析状态。
- 发送前再次按当前家庭、宝宝和周期构建上下文，不缓存业务摘要。
- 综合概览同时提供已开启的睡眠、喂养、尿布、生长和健康两期数据。
- 跨类别回答只允许描述同步变化和可能关联，不允许声称因果关系。

## 4. 不实现

- 不修改 Room、数据库版本、DAO 或同步协议。
- 不保存周期选择、分析结果或会话历史。
- 不新增业务页面入口、导航参数或独立趋势页面。
- 不计算医学结论、因果关系或健康评分。
- 不修改 Supabase、Edge Function 或模型供应商协议。

## 5. 数据规则

```text
最近 N 天：now - N days <= timestamp <= now
前 N 天：now - 2N days <= timestamp < now - N days
```

- 未来时间记录不进入任一周期。
- 本期没有主类别记录时，该专项分析不可用，即使前期存在记录。
- 前期没有记录时仍可分析，但上下文必须明确写为“无记录”。
- 综合概览至少一个已开启类别在本期有记录才可用。
- 原始备注和健康描述继续执行现有清理与长度限制。

## 6. 页面状态

- 周期选择位于快捷分析标题和卡片之间。
- 卡片与当前分析范围条展示统一周期，例如“最近 14 天 · 对比前 14 天”。
- 选择周期不会自动发送请求。
- 已选择分析范围时切换周期，会更新建议问题并重新校验记录。
- 生成过程中不可切换周期，避免请求上下文含义变化。

## 7. 验收标准

1. 可选择 7、14、30 天，默认 7 天。
2. 本期与前期时间边界不重叠。
3. 睡眠、喂养、健康分别生成两期摘要。
4. 综合概览包含已开启类别的两期摘要和非因果提示。
5. 本期无主数据时不调用模型。
6. 切换宝宝、家庭或账号后不复用业务摘要。
7. 不修改 Room、后端、导航和业务页面。
8. 相关单元测试与 Kotlin 编译通过。

## 8. 后续阶段

- 本地会话历史、搜索、删除和按宝宝筛选。
- 回答跳转到具体记录或保存为备注。
- AI 分析缓存。

以上能力涉及 Room 表结构或业务写入，实施前必须单独确认。
