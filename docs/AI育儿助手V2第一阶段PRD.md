# Baby Tracker「AI 育儿助手」V2 第一阶段 PRD

> 文档状态：已实现
> 文档版本：0.2
> 更新日期：2026-07-24
> 阶段范围：助手页集中快捷分析与统一对话上下文

## 1. 阶段目标

在现有 AI 育儿助手页面内提供睡眠、喂养、健康和近期概览四类快捷分析，让用户无需自己组织数据范围，也能基于当前宝宝的已有记录发起问答。

本阶段不在睡眠、喂养、健康或统计页面增加 AI 入口，不建设独立分析页面，不新增导航参数。

```text
AI 助手空态
  ├── 最近睡眠
  ├── 近期喂养
  ├── 健康整理
  └── 近期概览
          ↓
选择分析范围 → 填入建议问题 → 用户确认发送 → 沿用上下文追问
```

## 2. 用户问题

当前助手会根据问题自动选择近期记录，但用户需要先知道“可以问什么”，也不容易确认本次分析使用了哪些数据。

本阶段解决：

1. 用户进入 AI 助手即可发现四类可分析能力。
2. 用户选择分析类型后自动获得可编辑的问题草稿。
3. 页面明确显示当前会话的数据范围。
4. 后续追问沿用同一上下文。
5. 无记录或数据权限未开启时不产生模型调用。
6. 切换宝宝、家庭或账号后不复用旧上下文。

## 3. 范围

### 3.1 本阶段实现

- AI 助手空态增加 2×2“快捷分析”区域。
- 支持最近睡眠、近期喂养、健康整理和近期概览。
- 卡片展示可分析、暂无记录、数据未开启或检查中状态。
- 点击可用卡片后建立会话上下文并填入建议问题，不自动发送。
- 消息区与输入区之间展示可移除的上下文条。
- 明确入口上下文优先于原有问题关键词分类。
- 发送前重新读取当前宝宝记录并再次检查数据是否存在。
- 上下文生命周期与核心映射单元测试。

### 3.2 本阶段不实现

- 不在睡眠、喂养、健康和统计页面增加入口。
- 不增加 AI 导航参数或修改返回栈。
- 不新增 Room 表，不保存历史会话。
- 不修改数据库版本、Supabase 或后端模型协议。
- 不自动发送问题，不让 AI 新增、修改或删除记录。
- 不建设 RAG、语音、图片、主动洞察或周期对比。

## 4. 信息架构

```text
AI 育儿助手
├── 当前宝宝与数据使用说明
├── 模型选择
├── 空态
│   ├── 快捷分析
│   └── 常见问题
├── 对话区
├── 当前分析范围
└── 输入区
```

快捷分析只是对话的起始方式，不是四个独立模块，也不增加标签页。

## 5. 快捷分析

| 卡片 | 主要数据范围 | 建议问题 |
|---|---|---|
| 最近睡眠 | 最近 7 天睡眠，可附带最近 3 天喂养 | 帮我分析最近的睡眠情况 |
| 近期喂养 | 最近 3 天喂养，可附带最近生长记录 | 最近喂养记录有什么变化 |
| 健康整理 | 最近 30 天健康记录 | 帮我整理近期健康情况 |
| 近期概览 | 设置中已启用的多类近期记录 | 综合解读宝宝的近期记录 |

规则：

- 快捷分析只在消息为空时展示。
- 有记录时显示“可分析”；无记录时显示“暂无记录”。
- 总开关或对应类别关闭时显示“数据未开启”。
- 状态检查期间显示“正在检查”。
- 点击只选择范围并填写问题，不自动调用模型。
- 选择另一张卡片会替换当前上下文，不叠加范围。

## 6. 无数据与设置状态

- 无相关记录：不调用模型，提示当前宝宝暂无对应记录。
- 近期记录总开关关闭：提示前往助手设置开启。
- 对应类别关闭：同样视为数据未开启。
- 发送前记录被删除：恢复问题草稿并提示无记录，不发送空分析请求。
- 本阶段不跳转到新增记录页面。

## 7. 会话上下文

上下文条位于消息区与输入区之间：

```text
当前分析范围
最近睡眠 · 最近 7 天                         移除
```

规则：

- 第一次发送后上下文继续保留，后续追问沿用。
- 移除后，后续问题恢复自动关键词分类。
- 生成中禁止移除，避免一次请求的数据含义发生变化。
- 当前回答下方继续展示实际使用的数据类别。

以下情况清除上下文、草稿和相关提示：

- 切换当前宝宝。
- 切换当前家庭。
- 退出登录或关闭 AI 助手。
- 用户清除当前会话。

## 8. 数据与隔离

上下文只保存枚举类型：

```kotlin
enum class AiAnalysisSource {
    SLEEP,
    FEEDING,
    HEALTH,
    OVERVIEW,
}
```

禁止在上下文中缓存家庭 ID、宝宝 ID、业务记录正文或摘要副本。每次发送前必须使用当前 `BabyController`、当前家庭会话和 Repository 重新构建摘要，避免旧数据或跨宝宝复用。

明确分析来源存在时优先使用该来源；没有来源时继续使用现有问题自动分类。

## 9. 页面状态

| 状态 | 页面行为 |
|---|---|
| 正常空态 | 显示快捷分析和常见问题 |
| 选择快捷分析 | 显示上下文条并填入建议问题 |
| 已有对话 | 隐藏快捷分析，保留上下文条 |
| 无相关记录 | 不调用模型，显示具体提示 |
| 配置不可用 | 保留草稿和上下文，禁用发送 |
| 生成中 | 禁止替换或移除上下文，允许停止 |
| 生成失败 | 保留上下文和用户问题，允许重试 |
| 切换宝宝或家庭 | 取消请求并清空会话上下文 |

## 10. 视觉与组件

- 复用 `AppCard`、`AppChip`、`AppTextButton`、`AppInput`。
- 快捷卡片属于 AI 页面内部布局，不新增设计系统组件。
- 四张卡片使用统一主题色，不引入四套强调色。
- 选中卡片与上下文条使用 `primaryContainer`。
- 无数据状态使用文字表达，不能只依赖颜色。
- 本阶段不修改任何业务页面 UI。

## 12. 测试计划

单元测试覆盖：

- 四类建议问题映射。
- 近期记录总开关和分类开关。
- 明确来源优先于问题自动分类。
- 无记录结果的识别。
- 切换宝宝、家庭和清除会话时的上下文清理逻辑。

默认验证：

- 单元测试。
- Lint。
- Debug 构建。

除非用户明确要求，不进行模拟器验证。

## 13. 验收标准

1. 四类快捷分析只出现在 AI 助手页面。
2. 睡眠、喂养、健康和统计页面没有新增 AI 入口。
3. 点击快捷卡片只填入问题，不自动发送。
4. 页面展示并允许移除当前分析范围。
5. 后续追问沿用所选范围。
6. 无记录或数据未开启时不调用模型。
7. 发送前重新读取当前宝宝数据。
8. 切换宝宝、家庭、账号或清除会话后不保留旧上下文。
9. 不修改 Room、Supabase、导航和同步流程。
10. 单元测试、Lint 和 Debug 构建通过。
